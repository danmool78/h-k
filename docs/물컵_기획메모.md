# 물컵: 동승자 멀미를 줄이는 운전 (기획 메모)

> 작성 2026-10-29 · 앱 이름 미정 (가칭 "물컵") · 이 저장소의 새 방향 (안기다려에서 전환)
> 접수 마감 2026-11-15, 2차 실연 심사 2026-12-03~04 (실제 동작하는 앱 필요)

## 한 줄 소개

화면에 물컵 하나를 띄우고, 물이 넘치지 않게 운전하면 동승자가 멀미하지 않는다.

## 왜 바꿨나

- 안기다려(대기 없는 충전 경로)는 순정 내비가 이미 실시간 빈자리를 보여 줘서 차별점이 "도착 시점 예측" 하나로 줄었고, 그 효과도 휴게소가 실제로 차는 날에만 나타났다
- 공공데이터(충전기 상태)가 불안정했다 (2026-10-29 4시간 넘게 응답 없음)
- 물컵은 외부 데이터 없이 차 안의 신호만으로 동작하고, 순정 기능과 겹치지 않는다

## 핵심 개념

1. **물컵:** 차의 앞뒤·좌우 가속도에 따라 물이 출렁인다. 물이 넘치지 않게 운전하는 것이 목표
2. **넘친 양 = 멀미 누적량:** 넘친 양을 계속 쌓는다. 부드럽게 달리거나 쉬면 천천히 줄어든다 (몸의 회복)
3. **동승자에 따른 난이도:** 물 높이로 조절. 아이·노약자·임산부·멀미가 잦은 사람은 물을 높게 (쉽게 넘침), 혼자면 낮게 또는 끔
4. **경고:** 누적량이 기준을 넘으면 단계별로 알림
   - 주의: "찰랑" 소리 + "다음 구간은 부드럽게"
   - 위험: "동승자 멀미 위험이 높아요. 15km 앞 휴게소에서 쉬어 가세요" → 원하면 내비 경유지 추가
   - 차량 조치: 외기 유입·온도 낮춤 (HVAC 제어, Coming Soon → 열리면 추가)
5. **학습:**
   - 운전 습관: 이 운전자가 어디서 많이 넘치는지 (진출로, 신호 출발, 굽은 길 등) → 내비 다음 안내와 합쳐 미리 예고
   - 동승자별 기준: 동승자가 "속이 안 좋아"라고 하면 그 사람의 기준을 낮춤 → 쓸수록 개인에 맞춰짐
6. **도착 후 리포트:** 어디서 얼마나 넘쳤는지 지도, 동승자 편안함 점수

## 과학적 근거

- ISO 2631-1은 멀미 위험을 흔들림을 시간에 걸쳐 누적한 **멀미 누적량(MSDV, Motion Sickness Dose Value)** 으로 보고, 이 값에 비례해 증상이 나타나는 비율을 추정한다
- 0.1~0.5Hz(2~10초 주기)의 느린 흔들림이 멀미를 가장 잘 일으킨다 (가다 서다, 굽은 길에서 계속 핸들을 돌릴 때)
- 물컵의 출렁임 주기를 이 대역에 맞추면 "넘친 양 ≈ 멀미 누적량"이 된다
  → 발표: "물컵은 비유이고, 속은 국제 규격의 멀미 지표"
- 기획서에 쓰기 전에 규격 원문·논문 수치를 다시 확인할 것

## 신호

Pleos Playground에서 지금 쓸 수 있는 SDK는 **Vehicle State, NaviHelper 두 가지뿐**이다 (2026-10-29 기준 FusedLocation·TTS·STT·Vehicle Control은 "Coming Soon").
→ 핵심 기능은 이 두 SDK만으로 만든다. 에뮬레이터·공모전 단계는 권한 선언만으로 사용 가능 (승인은 App Market 등록 때).

Vehicle SDK 2.3.2 (SDK 파일 직접 확인) + `CAR_DRIVE` 권한 문서 (주행 중 호출 제한 없음):

| 필요한 값 | 출처 |
|---|---|
| 속도 | 주행 거리 변화 (`getTripInstantaneousDrivingDistance`, `getCurrentDistanceDriven` + 변화 알림) ÷ 시간 |
| 앞뒤 가속도 | 속도 변화 + 브레이크 페달 (밟음/안 밟음, 감속 시작 감지) |
| 좌우 가속도 ① | 속도² × 곡률. 곡률은 **전륜 조향각** (`getCurrentSteeringWheelAngle`, 바퀴 각도라 조향비 불필요) ÷ 축간거리 |
| 좌우 가속도 ② | 속도 × 방향 변화율. 방향은 NaviHelper 현재 위치의 `heading` (①과 교차 확인) |
| 앞으로 올 움직임 | NaviHelper 회전 안내 `TBTInfo`(종류·남은 거리·설명), 주의 지점 `CautionPoint`(종류·남은 거리) |
| 동승자 | 좌석별 탑승·안전벨트 (Seat) |
| 속도·가속도 직접 값 | 없음 |

확인할 것: 주행 거리 값이 들어오는 간격과 단위 (0.1km 단위면 속도가 너무 거칠다 → 보정·위치 기반과 섞기)

설계: 물컵 계산은 "앞뒤·좌우 가속도"만 받게 하고, 그 값을 가져오는 곳(`MotionSource`)을 바꿔 끼울 수 있게 한다.
- 실제 차가 가속도를 주면 그대로
- 안 주면 조향각 + 속도로 추정
- 시연은 녹화한 주행 시나리오 재생 (에뮬레이터에는 실제 움직임이 없으므로 실연 심사에서도 이 방식이 가장 안정적)

## 안전 설계 (운전 중 화면 주시 방지)

- 주행 중 화면은 한눈에 보이는 단순한 물컵 하나. 숫자·글자 없음
- 주된 피드백은 소리 ("찰랑")
- 자세한 점수·지도는 도착 후
- 뒷좌석 동승자가 자기 화면으로 같이 보는 방식도 검토 (아이에게는 놀이)

## 쓰는 SDK

| SDK | 용도 | 신청 |
|---|---|---|
| Vehicle | 전륜 조향각, 브레이크, 주행 거리, 좌석 탑승·벨트, (HVAC 제어는 Coming Soon) | 조회 불필요, 제어 필요 |
| NaviHelper | 현재 위치·진행 방향, 다음 회전 안내, 주의 지점, 휴게소 경유지 추가 | 불필요 |
| TextToSpeech / SpeechToText | 경고 안내, "속이 안 좋아" 음성 입력 — 아직 Coming Soon → 안드로이드 기본 TTS·Gleo로 대체 | 필요 |

안기다려에서 재사용: Gleo 음성 연동, 내비 경유지 추가, 운전 습관 학습 구조(DriveLearningService)

## 진행 순서

1. 이 기획 메모 ✅
2. 물컵 출렁임 계산 + 멀미 누적량 계산, 시나리오 재생으로 검증 (화면 없이)
3. 물컵 화면 + 경고 (소리, 휴게소 제안)
4. 실제 신호 연결 (에뮬레이터에서 확인되는 것부터)
5. 동승자 프로필·학습, 도착 후 리포트
6. 기획서 (접수양식), 시연 영상
