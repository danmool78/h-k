웹 데모는 학습을 근사로 흉내 냅니다(가상 학습 주행 수). 실제 앱은 차량·운전자별 주행 기록으로 계속 학습합니다.

계산 중…
어떻게 계산하나요? — 같은 여행을 수천 번 미리 달려보기 (몬테카를로)

왜 숫자 하나로는 부족할까요? 부산까지 배터리를 얼마나 쓸지는 그날그날 다릅니다. 바람, 정체, 내 운전, 기온, 그리고 휴게소에 도착했을 때 앞 차가 충전 중인지까지. 평균으로 한 번만 계산하면 "35% 남음" 같은 숫자 하나가 나오지만, 운이 나쁜 날엔 25%일 수도 있다는 건 알 수 없습니다.

그래서 컴퓨터 안에서 같은 여행을 수천 번 미리 달려봅니다. 매번 변수들을 "그럴 법한 범위 안에서" 조금씩 바꿉니다.

시뮬레이션정체운전휴게소 대기도착 배터리도착
1번째없음평소대로0분38%21:35
2번째약간빠르게0분33%21:30
3번째심함평소대로12분36%22:05
………………
2,000번째없음천천히3분41%21:48

결과를 모으면 "보통이면 21:40, 37% 남음 · 운이 나빠도 21:58, 31%"처럼 얼마나 틀릴 수 있는지까지 알 수 있습니다.

그다음 충전소·충전량마다 이 시뮬레이션을 다 돌려서, 운이 나빠도 도착 최소 배터리를 지키는 계획 중 가장 빨리 도착하는 것을 고릅니다. 예) 칠곡에서 60%까지: 운 나쁘면 24% → 탈락 · 칠곡에서 70%까지: 운 나빠도 31%, 5시간 10분 → 선택

쓸수록 정확해집니다. 차량과 운전 습관을 학습하면 "그럴 법한 범위"가 좁아져서, 같은 안전 기준으로도 덜 충전하고 더 빨리 갈 수 있습니다. 왼쪽의 가상 학습 주행 수를 올려 보면 아래 그래프의 띠와 분포가 좁아지는 걸 볼 수 있습니다.

기준이 되는 주행 시간·소모는 실제 앱에서는 차량 내비의 실시간 정보(교통·사고 반영)를 쓰고, 우리는 그 위에 불확실성과 충전소 대기를 더합니다.
