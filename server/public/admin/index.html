1. 전체 흐름

차량 신호 (주행 거리·조향각·브레이크·위치)→ 앞뒤·좌우 가속도→ ISO 2631-1 Wf 가중→ 물 기울기→ 넘친 양→ 멀미 누적량→ 안내·공조·창문

20Hz(0.05초)마다 한 번 돈다. 시연은 같은 계산에 주행 시나리오의 가속도를 6배속으로 넣는다. 앱과 웹 점검판이 같은 코드를 쓴다.

2. 차량 신호 → 가속도 MotionEstimator.kt

Pleos Vehicle SDK 에는 가속도 값이 없어 다른 신호로 추정한다.

속도·앞뒤 가속도

주행 거리 \(d\) (Odometer, km → m) 또는 내비 위치 변화(하버사인 거리)를 약 2초 구간의 기울기로 읽는다. 거리 값이 거칠게(예: 1m 단위) 와도 흔들리지 않게 하려는 것이다.

$$v = \frac{d(t) - d(t - \Delta)}{\Delta},\qquad a_x = \frac{v(t) - v(t - \Delta)}{\Delta},\qquad \Delta \approx 2\,\text{s}$$

브레이크를 밟는 중이면 \(a_x > 0\) 을 0 으로 본다. 2초 구간은 멀미 대역(2~10초 주기)보다 짧아 그 흔들림은 남는다.

좌우 가속도

조향각이 있으면 자전거 모형(정상 선회), 없으면 진행 방향의 변화율로 구한다. 왼쪽으로 도는 중이 +.

$$a_y = -\frac{v^2 \tan\delta}{L},\qquad \delta = \frac{\delta_\text{SDK}}{r_s},\qquad L = 2.9\,\text{m}$$ $$a_y = -v\,\dot\psi\quad(\text{조향각이 없을 때},\ \psi = \text{나침반 방향})$$

\(\delta_\text{SDK}\) 는 AAOS 관례대로 왼쪽이 음수. SDK 가 알려 주는 최대 각도가 60°를 넘으면 운전대 각도로 보고 조향비 \(r_s = 14\) 로 나누고, 아니면 바퀴 각도(\(r_s = 1\))로 본다. 가속도는 \(\pm 0.8g\) 로 자른다.

3. ISO 2631-1 멀미 주파수 가중 Wf Iso2631.kt

사람이 멀미하는 흔들림은 주기 2~10초(0.1~0.5Hz)의 느린 흔들림이다. ISO 2631-1 은 이것을 가중 함수 Wf 로 정해 두었고, 찰랑은 표준의 전달 함수를 그대로 쓴다.

$$W_f(s) = H_h(s)\,H_l(s)\,H_t(s)\,H_s(s)$$ $$H_h = \frac{s^2}{s^2 + \sqrt2\,\omega_1 s + \omega_1^2},\qquad H_l = \frac{\omega_2^2}{s^2 + \sqrt2\,\omega_2 s + \omega_2^2}$$ $$H_t = \frac{\omega_4^2}{s^2 + \frac{\omega_4}{Q_4}s + \omega_4^2}\ (f_3=\infty),\qquad H_s = \frac{s^2 + \frac{\omega_5}{Q_5}s + \omega_5^2}{s^2 + \frac{\omega_6}{Q_6}s + \omega_6^2}$$
구간뜻f (Hz)Q
\(H_h\)고역 (아주 느린 가속 제거)f₁ = 0.081/√2
\(H_l\)저역 (빠른 진동 제거)f₂ = 0.631/√2
\(H_t\)가속도-속도 전이f₄ = 0.25Q₄ = 0.86
\(H_s\)상향 계단f₅ = 0.0625, f₆ = 0.1Q₅ = Q₆ = 0.80

\(\omega_i = 2\pi f_i\). 매개변수는 ISO 2631-1:1997 기준이며 공개 구현 janiex/SimulinkMatlab (Matlab/ISO2631.m) 과 같다.

4. 물 기울기 · 넘침 · 멀미 누적 WaterCup.kt

물 기울기 = Wf 가중 가속도

가속하면 물은 뒤로, 왼쪽으로 돌면 오른쪽으로 쏠리므로 부호를 바꾼다. 단위는 g.

$$\theta_x = \frac{W_f\{-a_x\}}{g},\qquad \theta_y = \frac{W_f\{-a_y\}}{g},\qquad |\theta| = \sqrt{\theta_x^2 + \theta_y^2}$$

넘침

물 높이 \(\ell\) (0.05~0.95, 아이별 기준) 이 높을수록 여유가 작아 쉽게 넘친다.

$$F(\ell) = (1 - \ell)\,F_\text{max},\qquad F_\text{max} = 0.30\,g$$ $$r = K\,\max\!\big(0,\ |\theta| - F(\ell)\big)^2,\qquad K = 3\ \ \text{(g}^{-2}\text{s}^{-1}\text{)}$$

멀미 누적량 (몸의 회복 포함)

$$D(t + \Delta t) = D(t)\,e^{-\Delta t/\tau} + \int_t^{t+\Delta t} r\,dt,\qquad \tau = 600\,\text{s}$$

넘치지 않으면 10분마다 \(1/e\) 로 줄어든다. \(D = 1\) 이 이 아이가 멀미하는 수준이다.

값을 정한 방법

\(F_\text{max}\), \(K\) 는 주말 나들이 시나리오(도심 가다 서다 → 고속도로 → 진출로 → 산길 → 휴게소, 약 13분)로 맞췄다.

4-1. 위아래(z) 흔들림과 길 경사

ISO 2631-1 의 Wf 는 원래 위아래 흔들림의 멀미 가중이다. 방지턱, 오르내리는 길(약 6초 주기의 둔덕)은 위아래로 멀미를 일으킨다.

$$\theta_z = \frac{W_f\{a_z\}}{g}$$

위로 밀리면 물이 눌려 덜 기울고, 둔덕을 넘어 몸이 뜨면 물도 떠서 같은 쏠림에 더 기운다. 물이 느끼는 중력 \(g' = g + \bar a_z\) (\(\bar a_z\): 0.3초로 고른 위아래 가속, \(0.5g \le g' \le 1.5g\)):

$$\theta_h = \sqrt{\theta_x^2+\theta_y^2}\;\frac{g}{g'},\qquad |\theta| = \sqrt{\theta_h^2 + \theta_z^2}$$

넘침 판정(\(|\theta| > F(\ell)\))은 세 축을 합친 크기로 한다 — ISO 2631-1 의 축 합성 \(\sqrt{x^2+y^2+z^2}\) 과 같은 꼴, 축 계수 1.

길 경사: 물은 중력에 수평을 지키므로 차에 붙은 컵 안에서는 경사만큼 기울어 보인다 (화면 수면 = \(\theta - \text{경사}\)). 경사 자체는 흔들림이 아니라 멀미를 만들지 않으므로 넘침·누적량에는 넣지 않는다.

값을 얻는 곳

  • 실제 차: Pleos Vehicle SDK 에는 가속도 센서가 없다. 화면 기기의 안드로이드 가속도 센서(TYPE_ACCELEROMETER, 화면이 보이는 동안만)를 쓴다 (ImuFrame.kt, Imu.kt).
    • 위 = 센서 값을 1초로 고른 방향 (차가 내는 앞뒤·좌우 가속은 안 만큼 빼고) → 위아래 가속 \(a_z = (\mathbf a - \mathbf g)\cdot\hat{\mathbf u}\). 기기 방향과 상관없다.
    • 기준 위 = 처음 2초 넘게 멈춰 있을 때의 위. 앞 방향을 찾는 데만 쓴다 — 그 자리가 비탈일 수 있으므로 경사의 0 점으로 믿지 않는다.
    • 앞 = 곧게 가속·제동할 때(차량 신호의 앞뒤 가속 > 1.2 m/s², 좌우 < 0.5) 센서의 수평 가속 방향을 약 2초 모은 것. 왼쪽 = 위 × 앞.
    • 경사: 오르막이면 위가 차 뒤쪽으로 기운다 → 앞 올라감 \(= -(\hat{\mathbf u}-\hat{\mathbf u}_0)\cdot\hat{\mathbf f}\), 왼쪽 올라감 \(= -(\hat{\mathbf u}-\hat{\mathbf u}_0)\cdot\hat{\mathbf l}\).
    • 0 점(기준 자리 경사 = 기기 각도 오차) \(\theta_0\) 를 달리면서 계속 학습해 뺀다: 경사 \(= \theta_{센서} - \theta_0\). 곧게 일정하게 달릴 때만 (속도 > 4 m/s, 앞뒤 < 0.6, 좌우 < 0.8 m/s²).
      • 길 안내 중이면 지도 경사 \(\theta_{지도}\) = 실제 도로 높이(고도 타일)에서 지금 자리 앞뒤 25 m 의 \((z_{+25}-z_{-25})/50\) → \(\theta_0 \leftarrow \theta_0 + (\theta_{센서}-\theta_{지도}-\theta_0)\cdot dt/20\) (약 20초).
      • 지도가 없으면: 길은 길게 보면 오르내림이 상쇄되므로 \(\theta_0 \leftarrow \theta_0 + (\theta_{센서}-\theta_0)\cdot dt/600\) (약 10분). 옆 기울기는 늘 이 방식.
    • 물컵 수면 = 지금 차 기울기만큼 반대로 (물은 늘 수평). 기울기 출처: 기기 센서(최근 1초 안) → 없으면 길 안내 중 지도 경사(앞뒤만) → 없으면 0, 0.8초로 부드럽게 따라감 (MotionEstimator.updateGrade). 차량 SDK·내비 SDK 에는 차 기울기·고도 신호가 없다.
    • 시험(VerticalTest): 기기를 아무렇게나 돌려 붙여도 10% 오르막을 0.1±0.02, 방지턱 1.5 m/s² 를 찾는다. 8% 비탈에서 출발해도 지도가 있으면 2분 안에 평지를 0±0.015 로, 지도 없이도 30분 뒤 0±0.01 (처음 −0.08).
  • 시연 시나리오: 도심 가다 서다에 방지턱(0.5초 동안 ±2.8 m/s², 부드러운 운전은 속도를 줄여 ×0.35), 산길에 높이 진폭 0.35 m·파장 80 m 의 둔덕 — 시속 50km 에서 약 6초 주기, \(a_z = -A(kv)^2\sin kx\), 경사 \(= Ak\cos kx\).
  • 이 기기 센서 (LocalSensor.kt, web/Motion.kt): 웹 앱을 휴대폰·태블릿으로 열면 브라우저 devicemotion 을 곧바로 쓴다 (시연 시작 없이, 서버를 거치지 않음). 아래 휴대폰 시연과 같은 자세 찾기, 0.05초마다 평균해 한 시료, 값이 듬성듬성 와도 지난 시간만큼 채워 실제 시간대로. 순수 가속을 주지 않는 기기는 중력 포함 값의 1초 평균을 빼서 쓴다. 30초까지 끊겨도 같은 기록을 이어 간다 (그동안 흔들림 0). 화면에 자세·초당 값 수를 보인다. 권한을 묻는 기기는 열자마자 묻고, 안 되면(아이폰) 첫 터치 때 묻는다 — 터치 기기인데 값이 안 오면 "화면을 한 번 누르면…" 안내.
  • 휴대폰 시연: 놓인 자세와 상관없이 — 위 = OS 가 자이로로 구한 중력(중력 포함 값 − 순수 가속)의 반대 방향, 앞 = 처음 자세에서 휴대폰 위쪽(눕혔을 때)과 뒷면(거치대에 세워 화면이 운전자 쪽) 중 더 수평인 쪽, 왼쪽 = 위 × 앞. 앞뒤·좌우·위아래 = 순수 가속을 세 방향에 나눈 값. 경사 = 처음 자세를 평지로 보고 위가 기운 만큼 (휴대폰은 길 안내 지도가 없어 시연용). 이전에는 눕힌 자세만 가정해, 세워 두면 가속이 위아래로 잡혔다.

5. "지금 멀미" 로 기준 맞추기 Calibration.kt

이번 주행의 \(|\theta|\) 를 0.2초마다(그 구간의 최댓값) 남겨 두고, 버튼을 누르면 다른 물 높이로 다시 재생한다. 누적량은 물 높이에 대해 단조 증가하므로 이분 탐색으로 그 순간 누적량이 목표가 되는 물 높이를 찾는다.

$$\ell^* :\ D_\text{재생}(\ell^*) = 1.25$$

목표를 1.25 로 잡아, 다음에 같은 길을 달리면 멀미하기 전에 위험 경고(1.0)가 먼저 나온다. 이전 기준과 섞는다.

$$\ell_\text{새} = \ell_\text{이전} + 0.6\,(\ell^* - \ell_\text{이전})\quad(\text{처음이면 } \ell^*)$$

부드럽게 달렸는데도 멀미했으면 가장 예민하게(0.95), 아주 거칠게 달려야 멀미했으면 가장 둔하게(0.05).

멀미 없이 끝난 주행으로도 배운다

"지금 멀미" 로만 배우면 기준이 예민한 쪽으로만 움직여, 경고가 너무 이른 아이는 고쳐지지 않는다. 실제 주행(시연 제외)이 끝났을 때 아무도 "지금 멀미" 를 누르지 않았고, 이번 기록을 탄 아이의 기준으로 다시 재생한 최대 누적량이 1.25 를 넘었다면 그 아이는 생각보다 덜 예민하다. 이 주행이 겨우 1.25 에 닿는 물 높이 \(\ell^\circ\) 쪽으로 조금만 옮긴다.

$$\ell_\text{새} = \ell + 0.25\,(\ell^\circ - \ell),\qquad \max_t D_\text{재생}(\ell^\circ) = 1.25$$

0.25 로 작게 잡은 까닭: 멀미했는데 누르지 않았거나, 환기·휴식 안내 덕에 넘긴 주행도 섞여 있다. 바뀌면 주행 평가 안내 끝에 "○○ 기준은 오늘 멀미 없이 잘 와서 조금 덜 예민하게 맞췄어요" 라고 말한다. 시험: 20분 동안 꽤 큰 출렁임(0.25g)에 물 높이 0.8 → 0.665, 잔잔하면 그대로.

5-1. 아이별 민감 주기 (멀미 패턴 학습) Sensitivity.kt

표준 Wf 는 모든 사람에게 같다. "지금 멀미" 때마다 그 아이가 멀미한 흔들림 주기를 쌓아, 같은 주기대에 몰려 있으면 그 주기를 더 무겁게 본다. 학습 전에는 표준과 같다.

배우는 범위는 표준 멀미 대역(2~10초)보다 넓다: 0.03~0.8Hz (약 1.3~33초). 수평 흔들림 멀미 실험들(Donohew & Griffin 2004, Griffin & Mills 2002)이 다룬 범위다. 표준 Wf 는 10초보다 긴 주기를 크게 깎지만(20초 0.16배), 좌우 흔들림 실험에서는 약 30초 주기까지 거의 같은 세기로 멀미가 났다 — 연구마다 갈리는 대역이라 아이 기록으로 정한다 (docs/근거_논문.md).

연구 범위의 위쪽 끝 \(W_h\) (Iso2631.kt 의 Wh): Wf 의 가속도-속도 전이에 고역 0.02Hz 만 붙인 것. 0.25Hz 까지 평평, 그 위 옥타브당 −12dB (Donohew & Griffin 2004 의 좌우 가중).

$$W_h(s) = \frac{s^2}{s^2 + \sqrt2\,\omega_0 s + \omega_0^2}\cdot\frac{\omega_4^2}{s^2 + \frac{\omega_4}{Q_4}s + \omega_4^2},\quad f_0 = 0.02\text{Hz},\ f_4 = 0.25\text{Hz},\ Q_4 = 0.86,\qquad W_u = \max(W_f, W_h)$$

멀미 주기 찾기

멀미 직전 180초의 스펙트럼 \(P_s(f)\) 를 그 주행의 평소 스펙트럼 \(P_b(f)\) (같은 180초 구간들을 반씩 겹쳐 평균, Welch 방식 — 길이가 다르면 해상도가 달라 비교가 틀어진다)와 비교한다. 두 스펙트럼은 이웃 구간과 1:2:1 로 섞는다. 배우는 범위(0.03~0.8Hz) 안에서, 가중은 연구 범위의 위쪽 끝 \(W_u\) 로 (표준 Wf 로 보면 긴 주기는 처음부터 후보가 못 된다)

$$f^* = \arg\max_f\ \hat P_s(f)\cdot\frac{\hat P_s(f)}{\max(\hat P_b(f),\,\epsilon)}\cdot W_u(f)^2,\qquad \hat P = P / \textstyle\sum P$$

평소 기록이 270초보다 짧으면 비율 없이 \(\hat P_s W_u^2\) 만 본다. 시험: 20초 주기 가다 서다 8분 뒤 4초 좌우 흔들림 3분 → \(1/f^* = 4.02\)초. 4초 약한 흔들림 8분 뒤 20초 주기 큰 좌우 흔들림(긴 굽은 길) 3분 → 19.76초.

민감 주기와 강조 배율

최근 10번까지 기억하고, 최근 것일수록 무겁게(한 번 전 ×0.8) 로그 평균한다. 흩어짐은 옥타브 단위 표준편차 \(\sigma\).

$$f_p = \exp\frac{\sum_i w_i \ln f_i}{\sum_i w_i},\qquad G = 1 + (G_\max - 1)\cdot\max\!\Big(0,\ 1 - \frac{\sigma}{1\ \text{옥타브}}\Big)\cdot\min\!\Big(1,\ \frac{n - 2}{3}\Big)\quad(n \ge 3)$$

최대 배율은 표준이 멀미 대역으로 보는 주기에서 1.5, 표준이 연구보다 크게 깎는 주기에서는 연구 가중까지 올릴 수 있게:

$$G_\max = 1.5\cdot\max\!\Big(1,\ \frac{W_u(f_p)}{W_f(f_p)}\Big)$$

3번 미만이면 \(G = 1\). 시험: 5초 근처 3번 → \(G = 1.16\), 5번 → 1.49, 2.2·9.5·4.5초처럼 흩어지면 1.02. 20초 근처 5번 → \(G = 9.2\) (\(G_\max = 9.6\)).

강조 필터

물 기울기 = Wf 출력에 피킹 필터(RBJ Audio EQ Cookbook)를 건 값. 중심 \(f_p\) 에서 진폭 \(G\) 배, 멀어질수록 1배. 배율이 클수록 좁게 해서, 표준이 이미 무겁게 보는 이웃 주기까지 키우지 않는다: \(Q = 0.9\cdot\max(1, \sqrt{G/1.5})\) (20초 민감이면 \(Q = 2.23\)).

$$H_p(s) = \frac{s^2 + \frac{A}{Q}s + 1}{s^2 + \frac{1}{AQ}s + 1},\quad s = j\frac{f}{f_p},\quad A = \sqrt{G}$$

시험: 4초 민감(\(G = 1.50\))이면 4초 흔들림에 1.50배, 20초 흔들림에 1.02배. 20초 민감(\(G = 9.2\))이면 20초 흔들림에 9.2배, 5초 흔들림에 1.06배. MSDV 는 표준 그대로 기록된 가속도에 Wf 만 다시 걸어 계산한다(아이별 강조 제외).

6-1. 주행 평가 (주행이 끝날 때) TripReport.kt

언제: 시연이 끝나거나 멈출 때, 휴대폰 시연이 끝날 때, 실제 주행은 2분 넘게 달린 뒤 3분 넘게 서 있을 때(도착·주차, 신호 대기보다 길게). 달린 시간이 1분이 안 되면 평가하지 않는다. 결과는 화면에 덮어 보여 주고 한 줄로 말하며, 최근 20번을 기기 안에 남겨 지난번과 비교한다.

점수 (0~100): 거리와 상관없이 "어떻게 몰았나"

$$a_w = \frac{\text{MSDV}}{\sqrt{T}},\qquad S = 100\,e^{-\max(0,\ a_w - 0.2)/1.2} - \min\!\big(25,\ 0.5\,N_{10}\big)$$

\(a_w\): 앞뒤·좌우·위아래 Wf 가중 가속도의 평균 세기 (m/s²), \(N_{10}\): 달린 10분당 넘친 횟수. 0.2 m/s² 까지는 가다 서다만 해도 나오는 흔들림이라 깎지 않는다. 시연으로 맞춤: 부드럽게 \(a_w = 0.31\), 넘침 1번 → 90점 / 거칠게 \(a_w = 0.84\), 넘침 65번 → 33점.

  • 멀미 가능성: ISO 2631-1 부록 D — 구토할 수 있는 비율(%) \(\approx K_m\,\text{MSDV}\), 성인 남녀 섞인 경우 \(K_m \approx 1/3\). 표준은 위아래 기준이고 성인 기준이다 (아이는 더 예민할 수 있다).
  • 흔들림을 만든 운전 (넘으면 한 번, 기준의 2/3 아래로 내려와야 다시, 같은 종류는 3초에 한 번): 급제동 앞뒤 ≤ −3.0, 급출발 ≥ 2.5, 급회전 |좌우| ≥ 3.0, 방지턱·둔덕 |위아래| ≥ 2.0 m/s².
  • 잔잔했던 시간: 달린 시간 중 출렁임이 넘침 기준의 절반 아래였던 비율. 가장 출렁인 순간과 그 앞 4초의 가장 센 흔들림 축(물은 늦게 따라오므로). 멀미 주기: 주행 전체의 흔들림 주기 분석(8장).
  • 팁: 많았던 운전 두 가지, 멀미 주기(2~10초) 비율이 30% 넘으면 느린 출렁임 안내.

6-3. 물 양 = 평소 운전 습관, 도전 ChalrangEngine.kt

주행을 시작할 때 물을 평소 운전 습관만큼 채운다. 젠틀할수록 가득이다. 최근 5번 주행 점수를 최근일수록 무겁게(1:2:3:4:5) 평균한 \(\bar S\) 로:

$$\ell_0 = 0.35 + 0.55\,\frac{\bar S}{100}\quad(\text{기록 없으면 } 0.6)$$

도전: 출발 전(정차 중)에만 물컵 옆 +/− 로 5%씩 더 채우거나(최대 95%) 덜어 낼 수 있다(최소 20%). 물이 많을수록 작은 쏠림에도 넘친다: 넘침 기준 \(F(\ell) = (1-\ell)\,F_\text{max}\).

넘친 만큼 물이 준다: \(\dot\ell = -0.12\,K\max(0, |\theta| - F(\ell))^2\) (최소 12% 는 남김). 평소보다 더 채우고 출발해 줄어든 물이 3% 이하면 도전 성공.

물 양(화면·주행 평가)과 아이 멀미 누적·경고는 따로 계산한다. 아이 경고는 그 아이의 기준 \(F(\ell_\text{아이})\) 로만 정하므로, 물을 더 채워 도전해도 아이 보호는 달라지지 않는다.

설정 (기기 안에 저장)

음성 안내·"찰랑" 소리·안내 적게(주의·예고 음성 끔, 위험·휴게소는 함), 자동 환기·창문 열기 묻기·여는 정도(10/25/40%), 가는 길 미리보기·지형(인터넷), 주행 평가, 평소 습관으로 물 채우기, 휴대폰 시연 받기, 주행 기록 지우기, 아이 관리.

6-2. 가는 길 미리보기 (멀미 위험 구간) RoutePreview.kt

길 안내가 시작되면 가는 길에서 멀미가 날 만한 구간을 찾아 출발할 때 한 줄로 요약하고(아이가 탔을 때), 각 구간 1.2km 앞에서 다시 알린다. 화면에는 경로 띠(주황 = 조심, 빨강 = 위험, 초록 점 = 휴게소, 흰 점 = 지금)로 보여 준다.

재료

  • 내비 (Pleos NaviHelper): 회전 안내(TBT)와 주의 지점 — 급한 회전·유턴·회전 교차로·진입/진출로·과속 방지턱·급경사 내리막·좁은 길·파손된 길·낙석 주의(산길), 휴게소, 목적지까지 남은 거리·시간. 주행하며 새로 알게 된 지점은 출발점 기준 위치(\(D_0 - \text{남은 거리} + \text{지점까지 거리}\))로 쌓아 다시 계산한다.
  • 지형: 공개 고도 타일 (AWS Terrain Tiles, Mapzen Terrarium PNG: 높이 = R·256 + G + B/256 − 32768, 키 없음). 점마다 묻지 않고 그림 몇 장을 동시에 받아 그 안에서 읽는다 — 필요한 간격에 맞춰 줌을 고르고 최대 12장 (200km 길도 약 250m 간격으로 1~2초). 내비 SDK 가 경로 선을 주지 않으면 지금 위치 → 목적지 직선 위 100곳에서 읽어 경로 길이에 맞춰 늘린 추정이다.
  • 시연: 시나리오의 안내·방지턱·산길 굽이(반지름 100m 미만)와 길 높이(100m 마다).

판정: 모든 길에 같은 물리 기준 RoutePlanner.assess

안내 지점마다 점수를 주지 않는다 (같은 교차로를 내비가 몇 단계로 나누든, 저속 회전이든 산길 굽이든 지점 하나로 같게 세는 문제). 대신 길 모양을 편하게 달렸을 때 생기는 흔들림을 만들어, 물컵·주행 평가와 같은 ISO 2631-1 Wf 가중으로 잰다.

  1. 길 모양 (5m 마다): 굽은 정도 \(\kappa\), 높이 \(z\), 도로 속도 한도, 서는 곳(도심 시연은 교차로 회전), 과속 방지턱(내비 지점). 실제 도로 선(OSRM)이 있으면 그것, 없으면 내비 안내 지점으로 다시 그린 모양(6-4).
  2. 편한 속도: \(v = \min\big(v_\text{도로},\ \sqrt{2.5/|\kappa|}\big)\), 방지턱 ±10m 는 시속 20km, 서는 곳은 0, 가감속 1.5 m/s² 넘지 않게 앞뒤로 두 번 훑는다 (6-4 와 같다).
  3. 그 속도로 달릴 때의 가속: 앞뒤 \(a_x = \dfrac{d(v^2)}{2\,ds}\), 좌우 \(a_y = v^2\kappa\), 위아래 \(a_z = v^2\,\dfrac{z(s-100) - 2z(s) + z(s+100)}{100^2}\). 0.1초 간격 시간 순서로 (서는 곳에서는 8초 멈춤).
  4. 세 축에 Wf 를 걸어 1km 마다 평균 세기 \(a_{w,i} = \sqrt{\tfrac{1}{T_i}\int_{i} (a_{wx}^2 + a_{wy}^2 + a_{wz}^2)\,dt}\).
  5. 문턱 = 주행 평가 점수식(8장) \(100\,e^{-(a_w - 0.2)/1.2}\) 에서 그 1km 만 달렸을 때 70점 미만("찰랑") → 주의 (\(a_w \ge 0.63\) m/s²), 50점 미만("출렁") → 위험 (\(a_w \ge 1.03\)). 붙은 칸은 한 구간.
  6. 이유: 흔들림 몫이 25% 넘는 축 순서로 — 좌우는 그 구간의 굽이 안내(굽은 길·급한 회전 N곳), 앞뒤는 "가다 서다", 위아래는 "오르내림"(절반 넘으면 "심한 오르내림"). 다른 주의 지점(낙석 등)은 이유에만 붙는다.

그래서 미리보기와 주행 뒤 평가가 같은 잣대다: 미리보기 = "이 길을 편하게 달려도 이만큼 흔들린다", 주행 평가 = "실제로 이만큼 흔들렸다". 위험 구간 앞에 휴게소가 있으면 "그 휴게소에서 쉬어 가면 좋아요".

7. 흔들림 기록과 지연 DriveTrace.kt

0.1초마다 원인(차 흔들림 \(a_x, a_y\))과 결과(물 기울기 \(\theta_x, \theta_y\)), 속도, 물 높이, 누적량, 넘침 여부를 남긴다 (최대 2시간). 넘침·안내·차량 조치·"지금 멀미"는 사건으로 남긴다.

지연: 물이 차 흔들림을 얼마나 늦게 따라오나

차 흔들림이 물을 미는 방향 \(u = -a/g\) 와 물 기울기 \(\theta\) 의 정규화 상호상관이 가장 큰 시간차 \(\tau^*\) (0~5초)를 찾는다. 두 축을 합쳐 계산한다.

$$\rho(\tau) = \frac{\sum_k \big(u_x[k]\,\theta_x[k+\tau] + u_y[k]\,\theta_y[k+\tau]\big)}{\sqrt{\sum_k \|u[k]\|^2\ \sum_k \|\theta[k+\tau]\|^2}},\qquad \tau^* = \arg\max_\tau \rho(\tau)$$

거친 운전 시나리오에서 \(\tau^* \approx 0.3\sim0.4\)초. Wf 가 2~10초 주기만 남기므로 넓은 대역의 차 흔들림과 상관은 0.2 안팎으로 높지 않다 — 대략적인 값으로 본다.

8. 흔들림 주기와 MSDV ShakeAnalysis.kt

기록 구간(30초 이상)의 \(a_x, a_y\) 에서 평균을 빼고 해닝 창을 씌워, 로그 간격 60개 주파수(0.02~1Hz, 주기 50~1초)에서 이산 푸리에 변환을 직접 계산한다.

$$w[k] = \tfrac12 - \tfrac12\cos\frac{2\pi k}{N-1},\qquad X(f) = \sum_{k=0}^{N-1} w[k]\,a[k]\,e^{-i 2\pi f k T_s},\qquad A(f) = \frac{2\,|X(f)|}{\sum_k w[k]}$$

\(T_s = 0.1\)초. \(A(f)\) 는 사인파의 진폭을 그대로 준다 (6초 주기 진폭 1.5 m/s² → 1.5).

  • 가장 센 흔들림의 주기: \(1/\arg\max_f P(f)\), \(P = A_x^2 + A_y^2\)
  • 멀미에 가장 영향을 준 주기: \(1/\arg\max_f P(f)\,W_f(f)^2\)
  • 멀미 주기 비율: 로그 간격이라 구간 폭 \(\propto f\) 를 곱해 \(\dfrac{\sum_{0.1\le f\le0.5} P(f)\,f}{\sum_f P(f)\,f}\)

MSDV (Motion Sickness Dose Value)

기록된 앞뒤·좌우·위아래 가속도에 Wf 를 다시 걸어 계산한다 (물 기울기에는 아이별 강조가 들어 있을 수 있어서).

$$\text{MSDV} = \sqrt{\int \big(a_{wx}^2 + a_{wy}^2 + a_{wz}^2\big)\,dt}\quad [\text{m/s}^{1.5}]$$

시나리오 결과: 거친 운전 MSDV 약 22.0, 부드러운 운전 약 8.4 (방지턱·산길 위아래 포함). 거친 운전에서 가장 센 흔들림은 약 23~26초 주기(가다 서다)지만, 멀미에 가장 영향을 준 주기는 6~7초였다.

9. 3D 물컵 그리기 ui/CupView.kt

원뿔대 유리컵 (아래 반지름 \(R_b = 0.74\), 위 \(R_t = 1\), 높이 \(H = 2.1\), 유리 바닥 두께 \(b = 0.16\), 벽 두께 0.035) 안의 물을 기울어진 평면 수면으로 자른다. \(x\) = 오른쪽, \(y\) = 앞(화면 안쪽), \(z\) = 위, 컵이 놓인 바닥이 \(z = 0\). 받침 고리·접촉 그림자·물웅덩이도 같은 \(z = 0\) 평면에 같은 카메라로 그려 원근이 맞는다.

$$z_\text{수면}(x, y) = b + \ell (H - b) + k\,(\theta_x\,y - \theta_y\,x),\qquad k = \frac{H - b}{R_{t,\text{안}}\,F_\text{max}}$$

\(k\) 는 계산상 넘치는 순간(\(|\theta| = F(\ell)\)) 수면이 컵 가장자리에 닿도록 정했다. 실제 컵보다 기울기를 크게 보여 주는 것이다. 넘친 뒤에는 수면 경사를 가장자리까지 높이의 85%로 제한하고(그 이상은 물방울로), 가파를수록 수면을 몸통 색에 가깝게 칠하며, 같은 높이를 잇는 물결선(등고선) 5개로 기울기 방향을 보인다.

수면이 벽과 만나는 높이는 원뿔 벽 \(r(z) = R_b + c z\), \(c = (R_t - R_b)/H\) 위에서 풀어 구한다 (각도 \(\varphi\), 경사 \(g(\varphi) = p_x\cos\varphi + p_y\sin\varphi\)).

$$z(\varphi) = \frac{b + \ell (H - b) + R_{b,\text{안}}\,g(\varphi)}{1 - c\,g(\varphi)}\ \ \text{(} b \text{ 와 } H \text{ 사이로 자름)}$$

카메라는 뒤에서 앞을 보며 24° 내려다보는 원근 투영 (거리 8). 넘치는 동안 수면이 가장 높은 쪽 가장자리 ±40° 에서 초당 40개 물방울을 내고, 물방울은 \(\ddot z = -6\) 의 포물선으로 떨어진다. 물 색: 누적 0.6 전 파랑, 0.6~1.0 주황→빨강.

9-1. GPU 3D 물 ui/Water3D.kt

앱(Android 13+ RuntimeShader)과 웹(Skiko RuntimeEffect)이 같은 SkSL 셰이더로 화소마다 광선을 쏴 유리와 물을 계산한다. 지원하지 않으면 위의 2D 그림으로 그린다.

  • 물결: 원 안 48×48 격자에서 얕은 물 파동 방정식을 1/120초마다 푼다. 차의 가속은 벽에서만 들어간다 — 벽에서의 수면 경사 = 가속/중력 (경계 조건 \(\partial\eta/\partial n = \mathbf{s}\cdot\mathbf{n}\)). 그래서 가만히 있으면 수면이 그 경사의 평면으로 멈추고, 가속이 바뀌면 벽에서 물결이 생겨 반대편으로 건너가고 되돌아오며 서로 부딪혀 간섭 무늬를 만든다.
  • 비선형·부서짐: 물이 높은 곳에서 물결이 더 빨리 달린다(\(c^2 \propto\) 깊이, 세기 1.2) → 앞쪽이 가팔라지며 새 잔물결이 생긴다. 경사가 2를 넘는 곳은 부서지며 그 자리에 잔물결을 퍼뜨린다. 점성 항이 아주 잔 굴곡을 매끄럽게 하고, 평균을 0 으로 맞춰 부피를 보존한다.
  • 잔물결·메니스커스: 흔들릴수록 커지는 짧은 물결 4개(빛이 반짝이는 수면), 유리에 닿은 가장자리에서 말려 올라간 물(폭 0.022).
  • 수면 찾기: 광선과 평면의 교점에서 시작해 뉴턴법 4번으로 물결 높이까지 맞춘다. 옆 유리로 들어가는 경우는 안쪽 원뿔과의 교점(2차 방정식).
  • 빛: 프레넬 반사 \(F = 0.02 + 0.98(1-\cos\theta)^5\), 굴절(\(n = 1.33\)), 블린 하이라이트, 물속 거리에 따른 물 색, 바닥 빛 무늬(물결 라플라시안이 음수면 빛이 모임), 수면 바로 아래 밝은 띠.
  • 매끈한 법선: 48×48 격자를 선형 보간하면 칸마다 꺾인 자국이 비친다. 법선은 4×4 칸을 3차 균일 B-스플라인으로 이어 그 미분으로 구한다 (C² 연속). 원을 계단 모양 격자로 자른 경계에서 높이가 끊겨 벽 쪽 물 가장자리가 톱니처럼 보이지 않게, 컵 밖 3칸은 안쪽 이웃에서 수면 경사를 따라 이어 채운다.
  • 유리: 원뿔대 바깥면 프레넬 반사·가장자리 빛, 빈 컵 너머로 비치는 뒷벽, 세로로 길게 비친 조명 두 줄, 두께가 있는 테두리(안·밖 모서리 빛), 두꺼운 바닥. 옆에서 본 물에는 수면 물결이 모은 빛 줄기가 깊이에 따라 흐려지며 내려온다.
  • 기울기: 3D 물은 실제 컵처럼 덜 기울인다 (넘치기 시작할 때 약 15도, 최대 약 27도). 넘침은 물방울·물결로 보여 준다.

11. 한계와 확인할 것

기획서에 쓰기 전에 아래를 확인한다.
  • ISO 2631-1 의 Wf·MSDV 는 수직(z) 흔들림 기준이다. 찰랑은 위아래와 함께 차량 멀미 연구처럼 수평(앞뒤·좌우)에도 같은 Wf 를 적용하고 축 계수 1 로 합친다 — 근거 논문을 찾아 인용할 것.
  • 위아래·경사는 화면 기기의 가속도 센서가 있을 때만 나온다. 실제 차의 화면 기기에 센서가 있는지, 차 진동(엔진·노면 잔떨림)이 얼마나 섞이는지 확인할 것. 경사의 0 점은 지도 경사(길 안내 중)나 긴 평균으로 맞추므로 비탈 출발도 바로잡히지만, 길 안내 없이 출발 직후 몇 분은 출발 비탈만큼 어긋날 수 있다.
  • \(F_\text{max}\), \(K\), \(\tau\), 경고 기준(0.5·0.6·1.0)은 시나리오로 정한 값이다. 실제 아이의 멀미와 맞추는 것은 "지금 멀미" 보정이 한다.
  • 가속도는 직접 값이 아니라 추정이다. 에뮬레이터에서 주행 거리·조향각의 간격·단위를 확인할 것 (조향각이 바퀴 각도인지 운전대 각도인지 포함).
  • 3D 물컵의 기울기는 넘침이 보이도록 키운 것이고, 출렁임 주기는 실제 컵이 아니라 멀미 대역에 맞춘 모형이다 ("물컵은 비유, 속은 국제 규격의 멀미 지표").
  • 지연(상관 최대 시간차)은 상관이 낮아 대략적인 값이다.

11-1. 휴대폰 시연 (실제 차가 없을 때)

  1. 관리자가 /phone/ 에서 Google 로그인 → "시연 시작". 관리자는 Firestore admins/{uid} 문서로 지정한다.
  2. 휴대폰을 화면이 위로 오게 평평하게, 위쪽을 차 앞으로 들고 흔든다. 휴대폰 가속도(중력 제외) \(y\) → 차 앞뒤 \(a_x\), \(-x\) → 차 좌우 \(a_y\), \(z\) → 위아래 \(a_z\). 기울이면 길 경사(시작할 때를 평지로). 받는 가속도는 ±8 m/s² 까지 (손으로 세게 흔든 값을 차가 낼 수 있는 가속으로 자른다).
  3. 20Hz 로 모아 0.5초마다 새 문서 demo/live/{세션}/{순번} 로 올린다 (문서 하나에 초당 1번 넘게 쓰지 않게).
  4. 차량 앱·웹 점검판은 화면이 보이는 동안 demo/live 를 2초(시연이 없으면 최대 10초)마다 보고, 시연 중이면 0.4초마다 새 묶음을 받아(Firestore REST) 1초 쌓은 뒤 차 흔들림 대신 물컵에 넣는다. 10초 동안 새 묶음이 없으면 끝난 것으로 본다. 속도는 40km/h 로 둔다.

보안 규칙(server/firestore.rules): 시연 데이터는 누구나 읽기, 관리자만 쓰기, 그 밖은 모두 막음.
